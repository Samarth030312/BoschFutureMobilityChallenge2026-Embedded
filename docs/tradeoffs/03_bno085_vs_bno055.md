# Tradeoff 03 — BNO085 vs BNO055

## Chosen path (current source)

**BNO085** (CEVA-based 9-DoF IMU with SHTP protocol, 0x4A I²C address).

Evidence: `bno085.h` (all the SH-2 constants are BNO085-specific).

## Alternative considered (BNO055)

Bosch BNO055 — the predecessor. Also 9-DoF with onboard fusion, also Bosch part.

## Side-by-side

| Property | BNO085 (chosen) | BNO055 |
|---|---|---|
| Fusion algorithm | CEVA SH-2 firmware | Bosch native |
| I²C address | 0x4A (ADR low) | 0x28 or 0x29 |
| Protocol | SHTP (SH-2 packetized) | Direct register reads |
| Update rate (max) | ~1 kHz internal; 400 Hz quaternion out | 100 Hz quaternion (limit) |
| Self-calibration | Dynamic Calibration Daemon (DCD) | NDOF mode auto-calibrates |
| Magnetometer EMI handling | Mag-fused; DCD can mis-recalibrate | Similar |
| Datasheet maturity | Newer (2018+); active CEVA support | Older (2014); widely deployed |
| Driver complexity | Higher (SHTP framing + SH-2 reports) | Lower (register reads) |
| Community examples | Good (Adafruit, SparkFun) | Excellent (decades of use) |
| Per-frame accuracy estimate | Yes (Q12 accuracy field) | No |
| Linear-acceleration report (gravity-removed) | Yes (0x04) | Yes |
| Rotation Vector + Game Rotation Vector both available | Yes (0x05, 0x08) | Only one fused quaternion |

## What was gained by choosing BNO085

- **Per-frame accuracy field.** Available (Q12 rad). Currently unused but exists.
- **Two rotation vectors** (0x05 9-DoF, 0x08 6-DoF) — flexibility for future engineering.
- **Higher max update rate** for future high-bandwidth needs.
- **Newer chip** with longer-term support.

## What was sacrificed

- **More complex driver.** SHTP framing + SH-2 multi-report walker = ~440 LOC vs ~150 for BNO055.
- **No drop-in upgrade path from BNO055.** Different I²C address, different protocol — not interchangeable.
- **DCD complexity.** Dynamic Calibration Daemon can mis-recalibrate to garbage under EMI; the team's mitigation (sanity gate, wider yaw covariance) is non-trivial.

## When the team might switch

- **If BNO085 supply becomes unavailable.** Bosch chips have had supply issues; BNO055 alternative.
- **If a simpler driver is needed** for a quick-port to a different platform.
- **If a different sensor pinout is needed** for a redesigned PCB.

## Current cost-benefit reading

BNO085 is correctly chosen for forward-looking compatibility and feature breadth. The complexity premium (vs BNO055) is paid; the gains (Q12 accuracy, dual rotation vectors, higher rate ceiling) match the team's level of engineering.
